## Safe flow

1. Call capabilities. Reject mismatches before contacting the daemon.
2. Call `daemon status`. Reject stopped or incompatible daemons rather than implicitly starting one.
3. Privately snapshot existing public Workspace, Shell, Agent, Node projection, and integration JSON.
4. Record `config path`, validate it, and copy its bytes only to ignored private evidence if a complete configuration snapshot is required. Do not parse it or access Boomux state/runtime files.
5. Establish an event baseline with `events --json`.
6. Generate one collision-resistant prefix and persist the intended names before mutation.
7. Create the empty global Workspace with its prefixed name.
8. Resolve its exact global ID using `workspace.inspect`.
9. Obtain the exact local Node ID from `node.snapshot`. Do not rely on the `local` alias.
10. Create Coordinator, Builder, and Reviewer Shells separately with exact names, cwd, and argv.
11. After each weak create, use `node.snapshot` and `shell.inspect` to record the exact owner Workspace ID and Shell ID. Never infer IDs from human output.
12. Present each exact Shell. Poll `shell.inspect` for bounded startup completion and record its exact Run ID.
13. Subscribe from the baseline cursor and filter events by recorded Shell IDs while advancing across unrelated events.
14. Before cleanup, verify the exact owner Workspace contains no unrecorded Shell, Launcher, or Agent.
15. Close only recorded Shell IDs, verify `not_found`, then close only the recorded global Workspace ID and verify removal.
16. Never stop the daemon or invoke setup, update, uninstall, integration mutation, web, remote mutation, `desktop close`, or broad cleanup.

Create is idempotent only when an existing receipt already maps the stable session key to exact recorded IDs. Do not reclaim resources by prefix after an interrupted unrecorded mutation. Close is idempotent after the receipt records successful removal.

## Lifecycle and events

`shell.inspect` exposes:

- Shell status: `pending`, `running`, or `exited`.
- Exact Run fields: `id`, `generation`, `started_at_ms`, `ended_at_ms`, `exit_reason`, `exit_code`, `output_revision`, and `environment_has_run_id`.

The runtime adapter should normalize these without exposing Boomux entities as domain objects.

Event cursors are opaque `<stream-uuid>:<event-id>` values:

- Baseline request returns an atomic snapshot and cursor.
- Cursor requests return only later events.
- Retention is 8,192 events.
- A response contains at most 256 events.
- Different streams, evicted events, and future positions return `cursor_expired`.
- Graceful handoff preserves the stream. Cold daemon startup replaces it.
- Filtered events still advance the returned cursor.

Relevant event types are:

```text
workspace_created
workspace_closed
shell_created
shell_closed
run_started
run_exited
handoff_completed
```

`output_changed` is ordered but is not itself a lifecycle transition.

## Safety findings

- **F1:** Closing a native terminal window disconnects only its attachment. Boomux retains the PTY and child. There is no public programmatic detach command required by this spike.
- **F2:** `close(reference)` must mean destructive Shell cleanup. It must not represent window closure and must never invoke `desktop close`.
- **F3:** Attachment presence is not exposed in snapshots or lifecycle events. Process survival after closing a window requires the human gate.
- **F4:** Process PID is not included in `shell.inspect`. The manual probe process must privately record `process.pid`, `BOOMUX_SHELL_ID`, and `BOOMUX_RUN_ID`.
- **F5:** `boomux open` is human-only. `--takeover` matches the reference consumer and replaces only the controller for that exact Shell. It does not affect the other role Shells.
- **F6:** `exact_run_attachment` advertises internal protocol support, not a public expected-Run option on `boomux open`.
- **F7:** Public `open` can restart an exited Shell. Pre/post inspection detects a changed Run but cannot prevent the race between inspection and attachment. Never claim unconditional race-free exact-Run presentation.
- **F8:** `session open` has exact-current-Run behavior but requires Boomux Agent Session identity and is unsuitable for this generic terminal-runtime port.
