### Port behavior

```text
capabilities()
create(spec) -> opaque session ref
present(ref)
inspect(ref) -> lifecycle state
close(ref)
subscribe(refs, cursor) -> ordered lifecycle events
```

`create(spec)` accepts a stable idempotency key, role, absolute cwd, and argv. A repeated identical key returns the recorded opaque reference. A changed spec under the same key fails.

`inspect(ref)` maps Boomux `pending`, `running`, and `exited` states. The first observed Run becomes the recorded Run. A later different Run fails with `RunChanged` and never silently replaces the mapping.

`present(ref)`:

- rejects exited or changed Runs;
- permits pending Shells only for their first launch;
- uses no `--takeover`;
- polls `shell inspect --json` after `open`;
- requires the initially observed Run or the previously recorded exact Run.

`close(ref)` is destructive Shell cleanup, not terminal-window closure. It may only target a receipt-owned exact Shell ID. Confirm removal through JSON `not_found`.

`subscribe()` uses the local event stream. Filter Shell and owner-Workspace IDs, not the global Workspace ID. Advance the cursor through unrelated events. Reject out-of-order event IDs and return typed `CursorExpired` on stream replacement or retention expiry.

1. Read public `BOOMUX_SHELL_ID` and `BOOMUX_RUN_ID`.
2. Print one controlled JSON marker containing schema, role, PID, Shell ID, Run ID, and prefix.
3. Remain alive with a timer. It must not spawn a shell or child process.

`manual.mjs` modes:

| Mode | Permission | Behavior |
|---|---|---|
| `preflight` | Default | Requires an already-running daemon, captures public snapshots into ignored local evidence. |
| `create` | `--allow-live-mutations` | Creates empty global Workspace and three pending named Shells. Never opens windows. |
| `inspect` / `subscribe` / `probe` | Default | Reads exact receipt-owned state only. |
| `present` / `present-all` | `--allow-gui` | The only modes allowed to call `boomux open`. |
| `cleanup` | `--allow-live-mutations` | Refuses unknown membership, closes confirmed Shell IDs, then the confirmed empty global Workspace. |

Preflight must refuse when `daemon status --json` is not `running`, preventing an accidental daemon start. It should capture public `node snapshot`, `events`, integration list/status, and config path/validation before live creation.

The human gate closes the Builder terminal using the terminal emulator’s normal window close action, never `boomux desktop close` or `boomux shell close`. Then verify the same recorded Run ID and probe PID remain alive, re-present Builder with `--allow-gui`, and confirm Coordinator and Reviewer Run IDs are unchanged.
