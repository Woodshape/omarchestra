## Required fixes

### F1. Remove terminal-output scraping

`lib/adapter.mjs:423-457` uses `boomux read` and parses `OMARCHESTRA_BOOMUX_PROBE` from rendered terminal output. This contradicts `README.md:20`, the MVP boundary, and the request.

Required changes:

- Remove `commands.read`, `readProbe()`, probe-marker parsing, related fixtures, and `read` from the source-audit allowlist.
- Make `probe-process.mjs` write PID, role, `BOOMUX_SHELL_ID`, and `BOOMUX_RUN_ID` directly to an ignored owner-only evidence file supplied in its argv.
- Have the manual driver read that spike-owned evidence file and compare it with `inspect()`.
- Extend the source audit to reject terminal-read/output-scraping mechanisms.

### F2. Prevent adoption of a pre-existing prefixed Workspace

`lib/adapter.mjs:525-560` can run weak `workspace create`, receive a nonzero result such as “already exists,” inspect the matching name, and record that existing Workspace as spike-owned. Cleanup could then close user data.

Required changes:

- Before mutation, call JSON `workspace.inspect PREFIX`.
- Require and record an exact `not_found` precondition.
- If the name already exists, fail with `ownership_conflict` before mutation.
- Permit lost-result reconciliation only when the persisted precondition proved absence immediately before the attempted create.
- Add regression coverage proving a pre-existing matching Workspace is never adopted or closed.

### F3. Enforce preflight before live mutation

`manual.mjs:96-119` writes a standalone preflight file, but `create` does not require or link it. A user can run create directly with only `--allow-live-mutations`.

Required changes:

- Require create to receive and validate a generated preflight evidence path or token.
- Record that preflight identity in the ownership receipt before mutation.
- Validate that it contains the required public resource/integration baseline and predates mutation.
- Validate one exact eligible local Node before creating the empty Workspace. Current `create()` creates the Workspace before `#localNode()` runs.
- Record exact configuration bytes, or an explicit absent state, from the path returned by public `config path` into ignored private evidence. Path and validation output alone are not a configuration snapshot.
- Update the manual gate commands accordingly.

### F4. Correct the declared command and capability contract

The README command table does not match the implementation:

- README uses `boomux --json ...`; `lib/commands.mjs` emits `boomux ... --json`.
- README and required capabilities include `launcher.list`, but the adapter never calls it.
- `exact_run_attachment` is required even though generic public `boomux open` cannot use that capability.

Required changes:

- Document the exact argv order emitted by `commands.mjs`.
- Remove unused `launcher.list` command construction and capability requirements unless it is actually used.
- Remove `exact_run_attachment` from required features. Keep it documented as advertised but insufficient for guarded generic Shell presentation.
- Keep the exact-Run race documented.

### F5. Persist exact Run mapping from lifecycle events

`lib/adapter.mjs:683-714` only mutates a temporary subscription object when `run_started` arrives for a session without a recorded Run. It creates no opaque Run reference and persists nothing, so the next subscription can accept another raw Run silently.

Required changes:

- On a first valid `run_started`, persist the raw Run ID and a generated opaque Run reference before returning the event.
- Include the opaque Run reference in the normalized lifecycle event.
- Return `run_changed` for later conflicting Run IDs.
- Add coverage for a pending Shell started outside `present()` and observed first through `subscribe()`.
