**Status:** Design complete. No project files were modified. `spikes/boomux-runtime-adapter` does not yet exist, so implementation tests and source scans were not run.

## Test harness

Use Node’s built-in `node:test` and an injected fake executor.

The fake executor must:

- Record every `argv` and options object.
- Require exact canned responses.
- Reject unexpected calls, retries, and fallback commands.
- Assert `shell: false`.
- Never launch Boomux, a terminal, or a daemon.
- Model state changes after weak commands to simulate partial and ambiguous outcomes.

Fixtures should use distinct IDs:

```text
coordinator_workspace_id: coord-001
owner_workspace_id: owner-001
node_id: local-001
shell_ids: shell-001, shell-002, shell-003
run_ids: run-001, run-002, run-003
```

The coordinator and owner Workspace IDs must differ.

## Deterministic test matrix

### Capability and envelope tests

| ID | Case | Required assertion |
|---|---|---|
| `CAP-01` | Valid Boomux 1.8.0 capabilities | Accept `boomux.cli/v1`, protocol `49`, required JSON commands, required features, and typed error support. |
| `CAP-02` | Missing schema, command, feature, or protocol support | Fail before mutation with a typed compatibility error. Never fall back to version-only detection. |
| `CAP-03` | Malformed capabilities JSON | Fail closed. No daemon or mutation command follows. |
| `CAP-04` | Missing executable, stopped daemon, connection refusal | Return adapter `boomux_unavailable`. Never run `daemon start`. |
| `ENV-01` | Valid success envelope | Require `schema`, expected `command`, and `data`. Ignore documented additive fields. |
| `ENV-02` | Wrong schema, command, missing data, invalid JSON, or JSON array | Return a protocol error before interpreting resource data. |
| `ENV-03` | Typed error envelope on stderr | Dispatch on `error.code`, not message text. Preserve the message only as diagnostics. |
| `ENV-04` | Unknown error code | Fail closed. Do not retry or reinterpret it as success. |
| `ENV-05` | Human-readable output from a non-JSON command | Never parse stdout for IDs, status, or success details. |

Example error fixture:

```json
{
  "schema": "boomux.cli/v1",
  "command": "shell.inspect",
  "error": {
    "code": "not_found",
    "message": "shell is gone"
  }
}
```

### Events and cursors

| ID | Case | Required assertion |
|---|---|---|
| `EVENT-01` | Baseline | Store the snapshot and cursor from one atomic `events --json` response. |
| `EVENT-02` | Pagination | Preserve event-ID order across batches. Accept skipped IDs. Never sort by timestamp. |
| `EVENT-03` | Filtered events | Ignore unrelated Workspaces, Shells, and Runs while advancing the cursor past them. |
| `EVENT-04` | Output revisions | Accept skipped revisions, reject or ignore stale revisions, and retain exact Run identity. |
| `EVENT-05` | Cursor expiry | Discard the cursor and request one fresh baseline. Never retry the expired cursor. |
| `EVENT-06` | Stream replacement | Reset ordering and state when the stream ID changes. Never compare event IDs across streams. |
| `EVENT-07` | Malformed cursor or missing baseline snapshot | Return a protocol error and do not mutate local state. |
| `EVENT-08` | Duplicate event | Do not emit duplicate lifecycle transitions. |

Use event IDs such as `10, 14, 19` with non-monotonic timestamps to prove ordering uses IDs.

### Idempotency and unknown outcomes

| ID | Case | Required assertion |
|---|---|---|
| `IDEM-01` | Repeat successful create with the same adapter operation key | Return the existing receipt. Invoke the mutation once. |
| `IDEM-02` | Repeat close of an already absent recorded resource | Return an idempotent success without another close command. |
| `IDEM-03` | Close an absent unrecorded resource | Reject without invoking Boomux. |
| `OUT-01` | Partial creation | Stop at the failed Shell, return a partial receipt, and compensate only confirmed owned IDs. |
| `OUT-02` | Mutation timeout or transport loss | Reconcile through JSON snapshots. Do not retry the weak mutation automatically. |
| `OUT-03` | Exact postcondition proves creation | Adopt the one exact matching resource without replaying the command. |
| `OUT-04` | No postcondition or multiple matches | Return adapter `unknown_outcome`. |
| `OUT-05` | Close outcome is ambiguous | If the exact resource remains, return unknown and stop. If it is absent, accept only the recorded ownership receipt as proof of idempotent completion. |
| `OUT-06` | Boomux `outcome_unknown`, `unknown`, or `idempotency_expired` | Preserve the typed failure. Never convert it to success or perform an unkeyed retry. |

### Ownership-safe cleanup

The receipt must contain:

```text
adapter operation ID
unique prefix
coordinator Workspace ID
owner Workspace ID
Node ID
recorded Shell IDs
recorded Shell names, cwd, and command vectors
recorded Run IDs when present
```

| ID | Case | Required assertion |
|---|---|---|
| `OWN-01` | Cleanup with a valid receipt | Inspect exact recorded IDs before any destructive command. |
| `OWN-02` | Existing resource with a similar prefix | Leave it untouched. Never perform prefix-based cleanup. |
| `OWN-03` | Workspace contains an unowned Shell or Launcher | Refuse cleanup before closing anything. |
| `OWN-04` | Receipt ID differs from current ownership | Refuse cleanup. |
| `OWN-05` | Forged, raw, or unknown reference | Refuse cleanup without a CLI call. |
| `OWN-06` | Safe cleanup order | Close exact owned Shells first, verify absence, then close the exact empty Workspace. |
| `OWN-07` | Ambiguous close result | Stop and return unknown. Do not retry. |
| `OWN-08` | Tampered or incomplete receipt | Refuse cleanup. |
| `OWN-09` | Daemon-wide or focused cleanup request | Reject `daemon stop`, `daemon restart`, `close --focused`, and similar commands. |

`boomux shell close` and `boomux workspace close` are destructive cleanup operations, not detach operations.

### GUI boundary

| ID | Case | Required assertion |
|---|---|---|
| `GUI-01` | Presentation without explicit human authorization | Reject before execution. |
| `GUI-02` | Presentation argv construction | Build only `boomux open <exact-shell-id>` for the manual harness. |
| `GUI-03` | Automated tests | No test may invoke `open`, `--open`, `--takeover`, a terminal emulator, Hyprland, or a real Boomux executable. |

Detach, reconnect, PID survival, native-window reuse, and Hyprland tiling remain manual observations. Closing a native window must not be simulated with `shell close`.

### Allowed public commands

Read-only:

```text
capabilities --json
daemon status --json
workspace list --json
workspace inspect --json
list --json
shells --json
shell inspect --json
read --json
events --json
node snapshot --json
```

Controlled mutations:

```text
workspace create <unique-name>
shell create <exact-workspace> ...
shell close <exact-shell-id>
workspace close <exact-workspace-id>
```

Manual-only presentation:

```text
open <exact-shell-id>
```

Every other command must be rejected by the command allowlist.

### Must reject

- Direct Boomux state paths, including `.local/state/boomux`.
- SQLite, QML, Pi, Omarchy, or production orchestration imports.
- Rust modules, `.rs` files, Cargo APIs, or Boomux private protocol modules.
- Direct daemon sockets, Unix socket clients, or private runtime files.
- Hidden commands such as `__attach`.
- `exec`, `execFile`, `fork`, `sh -c`, `bash -c`, `shell: true`, and interpolated command strings.
- `daemon start`, `daemon stop`, `daemon restart`.
- Setup, update, uninstall, integration, web-server, desktop, launcher, agent, SSH, and remote-Node mutation commands.
- `close --focused`, prefix cleanup, name-based destructive targeting, and `--takeover`.
- Human stdout parsing for IDs or lifecycle state.

The audit should also assert that all executable paths are either the configured Boomux binary or adapter-owned temporary paths. Boomux state and sockets must never be opened directly.
