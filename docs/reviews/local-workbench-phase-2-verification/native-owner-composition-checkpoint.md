## Contracts closed

- `runner/main.ts start --state-dir <private-state> --runtime-dir <private-runtime>` holds one foreground store lock, one epoch, the framed Pi listener and an owner-only control socket. `open`, `hide` and `status` are one-shot clients addressing that socket with `--runtime-dir`; they never create a runner. Stdin EOF does not stop the owner. SIGINT/SIGTERM ends the foreground process. `inspect --path <local-repository>` does not open history. Offline `backup` requires **both** identical owned roots and a stopped owner; restore and schema migrations remain unsupported.
- On `open`, `desktop-command.ts` checks the *loaded* Companion identity, release version, ordered capability set, presentation contract, destinations and plugin generation. Every later call checks its loaded generation. Absent/incompatible/stale shell cannot report a successful open. A reloaded incarnation is never cleared or hidden by an old view. The runtime never installs or reloads a plugin; the sole desktop-command subprocess is the fixed `/usr/share/omarchy/bin/omarchy-shell` with bounded arguments and time.
- The Pi registry, challenged Adoption manager and durable Runner survive desktop hide/reopen. A restarted owner obtains a **new** epoch; only a surviving extension with fresh bridge proof recovers the prior Goal-scoped Run. View-only page state may reset on reopen, but exact durable selected Project/Goal context remains visible beyond page one. No legacy object-event transport is wired into the native owner.
- Projects, Goals, managed/observed/retired agents, checks and activity expose validated 64-record pages, totals and adjacent navigation. Runner refuses missing/non-adjacent page requests. The Qt console renders the actual page controls. Navigation-bookkeeping events are not user activity, so paging activity never shifts its own records. Admission caps still apply upstream. Unknown Git facts remain unavailable, never inferred from hidden rows.
