High-level architectural overview

Visible agents.
Native windows.
One control plane.

An Omarchy-native orchestrator where every working agent is the real interactive process visible in its own tiled terminal. The desktop console coordinates and observes those processes without hiding or replacing them.

Stage: Product scope locked · technical design pending Initial harness: Pi Terminal runtime: Boomux adapter Execution: Local, native windows

The product contract

The architecture is organized around three non-negotiable behaviors.

01

Visible execution

The terminal shown to the user contains the actual agent doing the work. The user may take control, then return it through an explicit reconciled handoff.

02

Persistent interaction

Closing a terminal window does not kill its agent. Opening the agent later reconnects to the exact surviving process.

03

Structured observability

The console receives trustworthy agent events from an in-process bridge. It never guesses semantic state from terminal pixels.

Why Boomux is replaceable

MVP responsibility

  • Own each agent PTY and child process
  • Keep agents alive after terminal windows close
  • Open, focus and reconnect native terminals
  • Report terminal process lifecycle

Not Boomux responsibility

  • Team Goals, roles or assignments
  • Fusion workflows and writer policy
  • Agent messages, artifacts or outcomes
  • The Agent Console's domain model
Boomux sits behind a narrow TerminalSessionRuntime port. A focused native PTY daemon can replace it later without redesigning the Team Runner or Omarchy UI.

MVP boundary

Included

  • Local machine and Pi agents
  • Native tiled terminal per agent
  • Persistent detach and reconnect
  • One Team Goal with visible roles
  • Validated YAML Team Profiles for role/model configuration
  • Structured status and activity feed
  • Managed/manual takeover with reconciled return
  • Focus/open exact agent terminal
  • Console approvals only for runner-owned decisions
  • Terminal redirect for Pi/harness-owned attention
  • Review-only and review-plus-command validation
  • Shared checkout with one writer
  • Durable goals, events and artifacts

Deferred

  • Remote Nodes and multiple harnesses
  • Per-agent worktrees and parallel writers
  • Embedded split-pane terminal rendering
  • Transcript scraping and synthetic chat
  • Network isolation/offline claims
  • Automatic full-reboot continuation
  • Named Task Capsules and portable context reconstruction
  • Native PTY-daemon replacement
  • Forking Boomux

Definition of success

The architecture is proven when a complete visible-agent workflow survives presentation-layer disruption without losing process identity or durable state.

Launch

Create a Team Goal and see every real interactive Pi agent appear in a native tiled terminal.

Observe

Track assignments, working state, tools, attention and outcomes from structured events.

Reconnect

Close an agent terminal, reopen it, and return to the same still-running process.

Navigate

Select an agent in the console and focus or present its exact terminal window.

Recover

Restart the Omarchy plugin without interrupting agents or losing the console projection.

Complete

Automatically produce a durable integrated result after the required review and command gates pass.
