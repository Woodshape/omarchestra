FIXED CONTRACT FINDINGS

F1 RESOLVED — Registry frames previously accepted a missing protocol and extra
top-level fields. The adapter now requires exactly protocol, type, messageId,
and body, validates the message identity and runner frame type, and fails open
on malformed or incompatible input.

F2 RESOLVED — observer.registered accepted arbitrary heartbeat timing and an
Adoption acknowledgement request could carry a different registryRevision.
The adapter now requires the fixed 5000 ms heartbeat, 15000 ms lease, current
registration attempt/source sequence, and exact registered revision.

F3 RESOLVED — A valid adoption.committed frame could enable management without
an acknowledgement, or with another proposal digest. Committed presentation
and bridge activation now require the exact proposal ID and digest previously
acknowledged from this extension instance on its current connection.

F4 RESOLVED — Managed-bridge delivery failure after a received durable commit
left the adapter observed and resumed observer telemetry. The adapter now marks
the exact acknowledged result managed and stops observer heartbeats before
best-effort presentation/bridge delivery. Delivery failure cannot recreate the
Observed Pi Session.

F5 RESOLVED — Process and extension identity factories accepted short opaque
strings. They now require bounded capability-shaped values of at least 32 ASCII
characters; defaults retain 128 random bits from randomBytes(16).

F6 RESOLVED — Concurrent public lifecycle callbacks could send increasing
source sequences out of order. All observer frames now share one session-local
send queue. Shutdown remains idempotent and cancels the exact heartbeat handle.

PUBLIC PI SURFACE REVIEW

Supported by Pi 0.84.4 public documentation:
- session_start and idempotent session_shutdown resource lifecycle;
- sessionManager.getSessionId() current Pi-session identity;
- ctx.mode, ctx.hasUI, ctx.isIdle(), and ctx.hasPendingMessages();
- agent_start and agent_settled lifecycle;
- ui_prompt_start and ui_prompt_end notification-only prompt lifecycle;
- named ctx.ui.setStatus() and postcommit ctx.ui.setTitle().

STOP FINDING R1 — The documented public surface does not provide complete
start/end lifecycle for slash-command execution. Extension commands bypass the
input event, and user_bash is a content-bearing pre-execution interception hook
with no matching completion event. ctx.isIdle() is documented for agent runs,
retries, compaction retries, and queued continuations, not arbitrary async
commands or user-bash execution. Therefore the adapter cannot prove that no
unclassified slash command or user-bash action is active when an Adoption ack
arrives. Inspecting input or wrapping shell execution would violate the locked
privacy/process boundary.

FEASIBILITY VERDICT

Exact same-process identity and current-connection acknowledgement are
supported by the public Pi surface and pass fake-only validation. Full safe
activity reconciliation is NOT established for unclassified slash-command and
user-bash execution. Per the implementation plan stop condition, Phase 5 is
stopped at this boundary rather than treating the fake host's explicit
idle/unknown controls as live proof. Resolve R1 through a content-free public
Pi command/activity lifecycle signal, or explicitly revise the locked contract,
before claiming full Phase 5 feasibility or proceeding to live validation.
